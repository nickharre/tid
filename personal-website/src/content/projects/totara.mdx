# Totara

Named after the Tōtara tree, a native New Zealand podocarp that lives over 1,000 years. Like the tree, software built with this framework is rooted in craft, built to endure.

## What It Is

A complete multi-agent team that turns rough ideas into shipped, tested, documented software through structured handoffs and quality gates. Seven specialized agents, each with a distinct role, operating principles, and collaboration protocol.

## Why It Exists

Most AI coding tools are single-agent: one model doing everything. That's like having one person be the PM, designer, developer, tester, and ops engineer. It works for small things. It falls apart for anything real.

Totara separates concerns the way real teams do. Each agent has a specialty, a quality bar, and a defined handoff protocol. The result is software that's been through the same rigour as a well-run team would produce.

## The Agents

- **Product Manager** — owns the "what" and "why"
- **Designer** — owns user experience and accessibility
- **Developer** — owns architecture and implementation
- **DevOps Engineer** — owns infrastructure and reliability
- **Tester** — owns quality and release validation
- **Delivery Lead** — gates handoffs, triages issues
- **Talent Manager** — audits capability, fills gaps

## What I Learned

The interesting challenge wasn't making agents write code. It was designing the handoff protocols, quality gates, and routing logic that prevent the kind of drift and rework that plagues real teams. The framework is as much about process design as it is about AI.
