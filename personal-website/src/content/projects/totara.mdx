# Totara — Spec-Driven Development Team

Named after a native New Zealand podocarp that lives over a thousand years. The metaphor is the point: software built with this team is rooted in craft and built to endure. Totara turns your AI coding assistant into a structured development team — seven agents, six quality gates, zero shortcuts.

## Why This Exists

Most AI coding workflows are chaotic. You ask your assistant to build something, it builds something, and you ship it hoping nothing breaks. There's no requirements phase. No design review. No one checking whether the acceptance criteria were actually met.

Totara imposes structure. Every phase has a fitness gate. Every handoff is verified. Every decision is documented. It's the process discipline that separates software that ships right from software that ships fast and breaks slowly.

## The Pipeline

Six phases, each owned by a named agent carrying deep expertise and strong opinions about their craft:

- **Requirements** — Marty (Product Manager). EARS notation, testable acceptance criteria, explicit scope boundaries.
- **UX Design** — Dieter (Designer). Every screen, every state — default, loading, empty, error, success, partial.
- **Architecture** — Margaret + Charity. Components, data model, API surface, security review.
- **Implementation** — Margaret (Developer). Boring, correct, maintainable code that works when it matters.
- **Testing** — James (Tester). Every AC has a passing test. No open Sev1/Sev2.
- **Release** — Joint sign-off. SLOs live, alerts tested, rollback rehearsed, security scans clean.

Two meta-agents run across all phases: **Gene** (Delivery Lead) gates every handoff, and **Peter** (Talent Manager) audits capability gaps before work begins.

## Highlights

- **Six quality gates** — no half-deliverables pass downstream, enforced at every phase transition
- **Issue triage taxonomy** — bugs routed by root cause, not symptom, to the right owner
- **Living documentation** — a product-level spec aggregates shipped features; tech debt lives in a register, not TODO comments
- **Capability audits** — gaps identified proactively before implementation starts, not discovered mid-sprint
- **Continuous learning loop** — user feedback and recurring issues become permanent team improvements
- **Two platforms** — works as a Kiro Power or a Claude Code CLAUDE.md drop-in

## Tech Stack

- Kiro (AI IDE with Powers support)
- Claude Code (CLAUDE.md agent configuration)
- Seven bespoke agent personas with structured handoff protocols
- MIT licensed, open source

## What I Learned

The hardest part was resisting the urge to make the agents do everything. The discipline is in the boundaries — each agent owns a slice, hands off with verified criteria, and trusts the next role to do its job. The structure is the feature. Without it, you don't have a team. You just have a very capable assistant who sometimes forgets what it was trying to build.
